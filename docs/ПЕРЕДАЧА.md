# rozkladka_common — передача в роботу

Створено 31.10.2026 порожнім; 0.1.0 — того ж дня (усе з переліку нижче, тести на векторах; знімок звірено з `openSnapshot` InTrack). InTrack 1.69.0 уже видає QR-коди активації й
приймає підписані знімки `.rzs`; застосунки цього ще не вміють.

## Що зробити (діалог застосунків)

1. Flutter-пакет (`lib/`, тести дзеркалять `lib/`, `flutter_lints`).
2. Ключ телефона ECDSA P-256 у захищеному сховищі, без експорту, з вимогою
   відбитка/PIN телефона на підписання: власний код для Android (Kotlin,
   Keystore, StrongBox де є) і iPhone (Swift, Secure Enclave) через
   MethodChannel. Відбиток/PIN — `local_auth`, лише за вибором людини.
3. Код телефона з відкритого ключа (SPKI DER) — алгоритм у протоколі;
   екран «Застосунок не активовано» з кодом великими літерами.
4. Сканування QR-коду (`mobile_scanner`) і відкриття файлу `.rza`;
   перевірка ES256 відкритим ключем InTrack (вшивається у збірку),
   `app`, `dev` = власний код, `scan_before`. Збереження `aid`, `sub`,
   `dept`; особа й підрозділ — лише для читання.
5. «Зберегти знімок» → `.rzs`: ECDH P-256 з відкритим ключем InTrack →
   HKDF-SHA256 → AES-256-GCM, підписаний заголовок, лічильник `n`
   зберігається в застосунку й лише зростає.
6. Тести на `docs/тестові_вектори.json`: код телефона, перевірка
   `activation_token`, розшифрування `snapshot_rzs_b64` тестовим ключем
   InTrack дає `snapshot_plain_b64`; власний `.rzs` розшифровує еталон.
7. Підключити в РозкладкаС, Е, Д; РозкладкаВ — через її діалог.

## Ключ InTrack у збірці

`lib/src/issuer_key.dart` — зараз ключ стенду. Застосунок належить тому
InTrack, чий ключ вшито. Перед робочою збіркою — ключ робочого InTrack за
процедурою першого ключа (розробляє InTrack).

## Межі

- Формат міняється лише разом з InTrack (`docs/modules/app-activation.md`).
- Без згадок ШІ; автори — Ярослав (ідея) і Любомир (розробка і супровід).
- Одна гілка `main`; бінарники в git не комітяться.

## 0.6.2 (18.11.2026) — умови зберігання

`storage_rules.dart`: класи складів `StorageClass` (l — легкий, опалюване
приміщення; m — середній, неопалюване; h — жорсткий, під навісом; vh — дуже
жорсткий, відкритий майданчик) і категорії майна `StorageCategory` (comms,
electro, sensitive, spares, batteries, measuring, medical — лише l;
vehicles — h, vh; other — будь-де). Табличка надходження RZI1: десята
колонка рядка `it` — код категорії (необов'язкова; немає — other).
Облік майна має дописувати її в кінець рядка.

## 0.6.3–0.6.4 (18.11.2026)

`StorageClass`: скорочення `short` (Л, С, Ж, ДЖ), `label` («Легкий (Л)») і
`explanation` — пояснення режиму зберігання для довідки (за Ярославом).
`allowedText` — через `label` («Легкий (Л) чи …»).

## 0.6.5 (22.11.2026) — структурний підрозділ в активації

QR-код / файл активації (RZA2 і JWS) приймає два необов'язкові поля:
`dept.kind` — `organ` чи `division` (орган чи підрозділ Держспецзв'язку) і
`unit` — `{ id, name }`: структурний підрозділ, що експлуатує застосунок.
`Activation.departmentKind`, `unitId`, `unitName`; без них — null, старі
коди працюють як раніше. InTrack має додати їх у видачу (повідомлено).
