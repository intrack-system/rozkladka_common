# Завдання діалогу Розкладок — усе в одному місці

Станом на 31.10.2026. Діалогів двоє: **InTrack** (`~/InTrack`) і **Розкладки**
(усі застосунки: `~/rozkladka_common`, `~/rozkladka_s`, `~/rozkladka_v`,
`~/rozkladka_e`, `~/rozkladka_d`). Цей файл — точка входу діалогу Розкладок.
Контракт з InTrack — `~/InTrack/docs/modules/app-exchange.md` (схеми баз) і
`~/InTrack/docs/modules/app-activation.md` (активація, знімки `.rzs`);
InTrack їх уже реалізував (1.69.0–1.70.0).

## Правила (обов'язково)

- Службові файли редактора й інструментів ніколи не потрапляють у git
  (перелік — у `.git/info/exclude` кожного клону). Комітити лише явно перелічені файли, без
  `git add -A` / `commit -a`; перед push — перевірити список і відсутність
  згадок ШІ. Історію всіх репозиторіїв 31.10 переписано — хеші змінились.
- Емулятори й збірки — лише на час використання, потім зупиняти.
- Схеми баз змінюються лише разом з InTrack: зміну описати й сказати
  Любомиру — InTrack оновить читач.

## Стан механізму захисту — у розробці

Активація й підписані знімки ще не перевірені й не застосовуються (InTrack
1.70.1: модуль вимкнений, приймає звичайні бази всіх застосунків). Тому в
застосунках активація — **сплячий другий режим**: нинішній перший запуск і
знімок `.db` не чіпати; у захищений режим телефон переходить назавжди, коли
вперше відкриє QR-код (файл) активації з InTrack. Так перехід вмикається
поступово з InTrack, без мережі.

## Черговість

### 1. `rozkladka_common` — активація й підписані знімки — 0.1.0 готово
Деталі — `docs/ПЕРЕДАЧА.md`, протокол — `docs/протокол_активації.md`, тестові
вектори — `docs/тестові_вектори.json`.
- Ключ телефона P-256 у Keystore / Secure Enclave; відбиток або PIN — лише
  якщо людина ввімкнула в картці доступу; код телефона.
- Екран «Застосунок не активовано», QR-код / файл `.rza`, перевірка
  підпису InTrack, `dev`, `exp`.
- **Дозвіл на трудовий рік (InTrack 1.70.3):** QR-код треба відсканувати до
  `scan_before` (тиждень від видачі; виданий у січні — щонайменше до 20 січня).
  Відсканований — телефон працює до `exp`: 31 грудня 23:59:59 за Києвом року
  видачі. Після `exp` — лише «Зберегти знімок», внесення заблоковане. 1–20
  січня — інвентаризація, знімків не роблять; новий дозвіл видається в січні,
  заздалегідь у грудні не видається.
- Знімок `.rzs` (ECDH → HKDF → AES-GCM, підписаний заголовок, лічильник).

### 2. РозкладкаЕ — перша робоча версія — 0.2.1 готово
`~/rozkladka_e/docs/ПЕРЕДАЧА.md`. Таблиця `equipment` (схема v1 уже
приймається InTrack): інвентарний номер, заводський номер, найменування,
опис своїми словами. Без активації — організація вводиться, як у скелеті; з активацією — особа й підрозділ з неї. Іконка своя.
Перша збірка в `builds/` і `Desktop\projects\etc\rozkladka_e_etc\builds\`.
Формуляр — коли Ярослав дасть розділи.

### 3. РозкладкаС — сплячий режим активації — 0.3.0 готово
Поруч із нинішнім першим запуском (не замість нього) — активація
(`organization` заповнюється з `dept`); «Зберегти знімок для обліку майна» —
`.rzs`. Схему `items` не міняти.

### 4. РозкладкаВ — сплячий режим активації + незмінний ідентифікатор — 2.54.0 готово
Те саме, що в РозкладкаС, плюс: кожен запис (вогнегасник, автомобіль)
отримує незмінний UUID і позначку видалення `deleted_at` замість стирання —
щоб бази з різних телефонів не дублювались. Зміну схеми описати для InTrack.

### 5. РозкладкаД — активація — 0.2.0 готово
Поля договорів — чекаємо Ярослава; до того — лише активація.

Коли РозкладкаС і РозкладкаВ перейдуть на `.rzs`, сказати Любомиру — InTrack
перестане приймати від них непідписані `.db`.

## Лишилось

- Перевірити на справжньому телефоні: ключ у Keystore, камера, відбиток, QR-код
  зі стенду, прийняття `.rzs` (емулятор тут не працює — немає KVM).
- iPhone: код є, збірка не перевірялась; Actions потребує доступу до приватного
  пакета — підключити, коли дійде до публікації.
- Що потрібно від InTrack — `docs/для_InTrack.md`.
